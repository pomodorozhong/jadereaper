## Gotchas

- **WebGPU needs a secure origin.** Open the game through `http://localhost` or `https`. Opening `index.html` from disk fails, and the game shows its "Cannot start" screen.
- **No `strip = true` in `core/Cargo.toml`.** On this machine's Rust toolchain, `rust-objcopy` cannot find `libLLVM.dylib`, so stripping fails during the build. The release profile leaves it out; the wasm is about 170 KB without it.
- **The built wasm is not committed** ([0007](decisions/0007-build-the-wasm-in-ci.md)). CI builds it for the deploy and the smoke test. Locally, run `./build.sh` after changing anything in `core/` or `content/game.json`, or the browser keeps running the old core; `npm start` only warns when the wasm is missing, and keeps serving so the Lightbox works without Rust.
- **`cargo fmt` skips `core/src/content.rs`.** `#[rustfmt::skip]` on its `mod` line in `core/src/lib.rs` keeps rustfmt off the generated file, so `content.mjs --check` and `cargo fmt --check` both pass. rustfmt's `@generated` marker did not skip it on stable Rust 1.99.
- **Biome formats all the JavaScript except `src/content.js`.** An override in `biome.json` turns its formatter off for that generated file, so `content.mjs --check` and `npm run lint` both pass. It is still linted. Run `npm run format` before committing JavaScript.
- **CI uses the current stable Rust**, with no pin. A new release can bring clippy warnings that fail the Checks workflow with no code change; fix them in their own PR.
- **Bundled fonts only hold the characters the game shows.** After adding or changing Chinese text in `src/` or `index.html`, run `tools/subset-fonts.sh` and commit `assets/fonts/`. Otherwise the font check in CI fails, and new characters fall back to a system font in the middle of a line.
- **The numbers font is picked by character.** `JR Numerals` in `style.css` applies Caveat Brush to digits and `+ % : , . ×` through `unicode-range`, which must match `NUMERALS` in `tools/fonts.mjs`. Caveat Brush has no `→`, so arrows use the text font.
- **The Pages site only holds listed paths.** `.github/workflows/pages.yml` copies `index.html`, `style.css`, `src/`, `wasm/` and `assets/`. A new top-level file or folder the game loads must be added to its copy step, or it works locally and 404s on https://pomodorozhong.github.io/jadereaper/. `PUBLISHED` in `tools/serve.mjs` must list the same paths, so `npm start` and the smoke test 404 on a file the deploy would miss. `LOCAL_ONLY` there lists tools that are served locally but not published, such as the Lightbox; the game must never load them. The site is served from `/jadereaper/`, so keep every path the game loads relative.
- **Content ids are generated.** Part ids, events, rigs, enemy kinds, skills, cards, rooms and moves live in `content/game.json`. After changing it, run `./build.sh` (it runs `node tools/content.mjs` first) and commit `core/src/content.rs`, `src/content.js` and `src/content.wgsl` with it; `npm test` fails when they are stale. State indices (`STATE` in `src/data.js`), the animation record layout and phases (`ANIM` and `ANIM_PHASE`, from `core/src/anim.rs`), button bits and reaction ids are still mirrored by hand between the core and `src/`.
- **The shader needs `src/content.wgsl`.** The renderer puts it in front of `src/shader.wgsl`, which uses its `P_*` part ids and `isFlat`. A part with no `case` in `shape()` is drawn as an ellipse, which is how the bosses' placeholder parts look.
- **Hit-stop delays the simulation.** A landed hit freezes every step for up to 0.09 s. A test that checks a state a few steps after a hit has to step past it, or turn on `reduce_motion`.
- **Things that must not count as kills** are removed by setting their health to negative infinity (a blot the Glutton eats); `reap` drops them quietly.
- **Wasm memory views go stale.** `src/main.js` rebuilds its `Float32Array` views of wasm memory on every read, because memory growth detaches old views. Keep that pattern when reading new buffers.
- **Scripted Lightbox checks.** `window.__lightbox` exposes the state, `loadFile` and `buildCharacter`, and the Lightbox's top-level functions (`applyPreset`, `ensure`, `invalidate`) are globals. Pass a preset through `applyPreset`, which fills settings an older preset lacks from `DEFAULTS`; assigning its settings to `S` directly leaves new settings undefined and the trace goes wrong. Dispatched pointer events cannot take pointer capture, so brushes, lassos and line drags only work with real clicks, and a hidden browser pane fires no animation frames.
- **Balance numbers** in `content/game.json` (skill timings, enemy and boss health, damage, wind-ups, room waves) were tuned only against the scripted bot in `core/src/bot.rs`. Treat them as placeholders until they are tuned in play.
- **The ?debug sizes and waddles cover the four small enemy kinds.** Bosses use their rig as it is.
