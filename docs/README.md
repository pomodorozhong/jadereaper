## Gotchas

- **WebGPU needs a secure origin.** Open the game through `http://localhost` or `https`. Opening `index.html` from disk fails, and the game shows its "Cannot start" screen.
- **No `strip = true` in `core/Cargo.toml`.** On this machine's Rust toolchain, `rust-objcopy` cannot find `libLLVM.dylib`, so stripping fails during the build. The release profile leaves it out; the wasm is about 170 KB without it.
- **The built wasm is not committed** ([0007](decisions/0007-build-the-wasm-in-ci.md)). CI builds it for the deploy and the smoke test. Locally, run `./build.sh` after changing anything in `core/` or `content/game.json`, or the browser keeps running the old core; `npm start` only warns when the wasm is missing, and keeps serving so the Lightbox works without Rust.
- **`cargo fmt` skips `core/src/content.rs`.** `#[rustfmt::skip]` on its `mod` line in `core/src/lib.rs` keeps rustfmt off the generated file, so `content.mjs --check` and `cargo fmt --check` both pass. rustfmt's `@generated` marker did not skip it on stable Rust 1.99.
- **Biome formats all the JavaScript except `src/content.js`.** An override in `biome.json` turns its formatter off for that generated file, so `content.mjs --check` and `npm run lint` both pass. It is still linted. Run `npm run format` before committing JavaScript.
- **CI uses the current stable Rust**, with no pin. A new release can bring clippy warnings that fail the Checks workflow with no code change; fix them in their own PR.
- **Bundled fonts only hold the characters the game shows.** After adding or changing Chinese text in `src/` or `index.html`, run `tools/subset-fonts.sh` and commit `assets/fonts/`. Otherwise the font check in CI fails, and new characters fall back to a system font in the middle of a line.
- **The numbers font is picked by character.** `JR Numerals` in `style.css` applies Caveat Brush to digits and `+ % : , . ×` through `unicode-range`, which must match `NUMERALS` in `tools/fonts.mjs`. Caveat Brush has no `→`, so arrows use the text font.
- **The Pages site only holds listed paths.** `.github/workflows/pages.yml` copies `index.html`, `style.css`, `src/`, `wasm/` and `assets/`. A new top-level file or folder the game loads must be added to its copy step, or it works locally and 404s on https://pomodorozhong.github.io/jadereaper/. `PUBLISHED` in `tools/serve.mjs` must list the same paths, so `npm start` and the smoke test 404 on a file the deploy would miss. `LOCAL_ONLY` there lists tools that are served locally but not published, such as the Lightbox; the game must never load them. The site is served from `/jadereaper/`, so keep every path the game loads relative.
- **Content ids are generated.** Part ids, events, rigs, enemy kinds, skills, cards, rooms and moves live in `content/game.json`. After changing it, run `./build.sh` (it runs `node tools/content.mjs` first) and commit `core/src/content.rs`, `src/content.js` and `src/content.wgsl` with it; `npm test` fails when they are stale. State indices (`STATE` in `src/data.js`), the animation record layout and phases (`ANIM` and `ANIM_PHASE`, from `core/src/anim.rs`), button bits and reaction ids are still mirrored by hand between the core and `src/`.
- **The shader needs `src/content.wgsl`.** The renderer puts it in front of `src/shader.wgsl`, which uses its `P_*` part ids and `isFlat`. A part with no `case` in `shape()` is drawn as an ellipse, which is how the bosses' placeholder parts look.
- **The instance format changes in four places at once.** An instance is 18 floats (72 bytes): `Inst` and `INST_FLOATS` in `core/src/defs.rs`, `INSTANCE_BYTES` and the vertex buffer layout in `src/renderer.js`, and the `vs` inputs in `src/shader.wgsl`. Change them together, or every part after the first is read from the wrong bytes.
- **Each part is a sheet in 3D, and all zeros is flat.** The last four instance floats are turn, lean, lift and bend (`Sheet` in `core/src/defs.rs`). With all four at zero the shader draws exactly what the flat renderer drew. The camera is a fixed parallel projection that leaves upright sheets at full height and shows a sheet lying on its back at `PITCH` (0.5) of its height; `PITCH` in `core/src/defs.rs` and `src/shader.wgsl` must match, as must `orient` in both. Leaning a sheet towards the camera shortens it quickly, because the camera looks down.
- **Each instance draws 48 vertices:** its ground shadow first (4 strips), then the sheet (4 strips, so it can bend). A flat part's shadow vertices are moved off screen. The shadow is its own geometry, so a lifted sheet's shadow stays on the ground; where a sheet is see-through (the flickering player), the shadow pass takes out the part the sheet's paper covers, so the result matches the old single pass.
- **Parts are ordered by depth in the core, not by a depth buffer.** `draw_rig` in `core/src/rigs.rs` turns each puppet about its ground point and sorts its parts back to front, with each part one `LAYER` behind the next in rig order and the swung weapon on top. At rest this is the rig's own order, so a new rig's parts must still be listed back to front.
- **Puppets are posed from the animation records.** `pose` in `core/src/rigs.rs` reads only a rig, its 3D numbers (`sheet` in `content/game.json`, `SheetPose`), the character's `Anim` record and a `Gait` (walk steps and a clock from the drawing side), so a test can feed it a made-up record. `update` builds the records before the draw list for this reason. Turns in a pose are for the puppet facing right; `draw_rig` mirrors them. A rig without `sheet` (the bosses, until #49) stays flat apart from turning round.
- **Turning round is drawn, not simulated.** When a character's facing changes, its drawn facing (`flips` in `Game`) takes `FLIP_TIME` (0.12 s) to turn through edge-on, keyed by the record's who and id. The simulation's facing changes at once, and none of it is in `state_hash`.
- **Aiming never turns a sheet edge-on.** The camera looks down, so a sheet turned a quarter turn vanishes. The charge turn is capped at each rig's `aim` (0.45 to 0.8 rad), and the stunned wobble stays short of a quarter turn. Leaning back a little makes a sheet taller (up to about 1.12 times at 0.46 rad); leaning forward shortens it fast, so keep `strike` and `sag` small.
- **Far paper fades into the ground.** Each instance carries its depth towards the camera from its puppet's ground point and the puppet's height (the last two floats). The shader adds each pixel's own depth within its sheet, divides by the height, and mixes the paper by `LOOK.depthFade` at `LOOK.depthDist` puppet heights away towards a tone between the ground colour (`GROUND` in `src/shader.wgsl`, which must match `fs_bg`) and a warm shade (`DEPTH_SHADE`), set by `LOOK.depthTone`. Fading into the ground alone is too subtle, because white paper is already close to the ground colour; shade reads far more. Parts outside a puppet send a height of zero and never fade, and a puppet at rest is at depth zero everywhere, so the rest look is unchanged.
- **The pose gallery** (`?gallery`) shows every rig in every pose in one grid, drawn by `build_gallery` in `core/src/gallery.rs` while the run is frozen (`update` returns early). Its columns are `GALLERY_POSES` in both `core/src/gallery.rs` and `src/gallery.js`, and the label margins (`GALLERY_TOP`, `GALLERY_LEFT`, `GALLERY_BOTTOM`) must match in both. One progress value scrubs every pose and also drives the clock, so trembles, shakes and wobbles step with it. It opens the ?debug panel, whose pose sliders tune the numbers live.
- **The ?debug pose sliders** set one rig's 3D numbers at a time through `jr_set_pose(rig, field, value)`, where `field` indexes `SHEET_KEYS` (generated from `tools/content.mjs` into both the core and `src/content.js`). "Copy values" adds a `pose` object shaped like each rig's `sheet`, ready to paste back into `content/game.json`.
- **A focused ?debug slider no longer swallows the pad.** On a menu, the pad's confirm and navigation take focus back to the screen's last focused button (`focusedButton` in `src/ui.js`). To test pad input without a pad, replace `navigator.getGamepads` in the console with a function returning a fake pad object, and `delete navigator.getGamepads` (or reload) afterwards, or a real controller stays ignored in that tab.
- **Menu highlights need `.pad-focus` for the gamepad.** The button highlight is `:focus-visible`, which browsers hide when code moves focus after a mouse click, so the pad moved an invisible cursor. `src/ui.js` adds `pad-focus` to the body when the pad (or arrow keys) navigate, `style.css` shows the highlight for `.pad-focus button:focus`, and moving the mouse removes it.
- **A browser only shows a controller after a button press** on a freshly loaded page; until then `navigator.getGamepads()` lists nothing.
- **The ?debug "Spin puppets" box** (`jr_set_debug_spin`) turns, leans, lifts and bends every puppet to check the sheets. It is drawing only and stays out of `state_hash`.
- **Measuring frame time.** A hidden browser pane runs animation frames at about 1 per second, so frame times from it mean nothing. Headless Playwright defaults to SwiftShader; pass `--enable-gpu --ignore-gpu-blocklist --use-angle=metal` (with `--enable-unsafe-webgpu`) to get the Mac's GPU, and time `GPUQueue.onSubmittedWorkDone` after each submit at normal frame pacing. With vsync off, frames queue up and the timings are meaningless. A built-in browser pane can also be throttled while it is showing (`document.hidden` false), for example when the app's window is not in front: it then gives a frame about every 60 ms. Before trusting a low frame rate, time the work inside each animation-frame callback; if that is tiny, the browser is throttling, not the game.
- **Hit-stop delays the simulation.** A landed hit freezes every step for up to 0.09 s. A test that checks a state a few steps after a hit has to step past it, or turn on `reduce_motion`.
- **Things that must not count as kills** are removed by setting their health to negative infinity (a blot the Glutton eats); `reap` drops them quietly.
- **Wasm memory views go stale.** `src/main.js` rebuilds its `Float32Array` views of wasm memory on every read, because memory growth detaches old views. Keep that pattern when reading new buffers.
- **Scripted Lightbox checks.** `window.__lightbox` exposes the state, `loadFile` and `buildCharacter`, and the Lightbox's top-level functions (`applyPreset`, `ensure`, `invalidate`) are globals. Pass a preset through `applyPreset`, which fills settings an older preset lacks from `DEFAULTS`; assigning its settings to `S` directly leaves new settings undefined and the trace goes wrong. Dispatched pointer events cannot take pointer capture, so brushes, lassos and line drags only work with real clicks, and a hidden browser pane fires no animation frames.
- **Balance numbers** in `content/game.json` (skill timings, enemy and boss health, damage, wind-ups, room waves) were tuned only against the scripted bot in `core/src/bot.rs`. Treat them as placeholders until they are tuned in play.
- **The ?debug sizes and waddles cover the four small enemy kinds.** Bosses use their rig as it is.
